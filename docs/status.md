## 进行中

- M1：codex（gpt-6.1-sol xhigh）两轮完成，已合并进集成分支（`c1dc1ee`）。在用户的 Galaxy Watch5 Pro 上实测（截图 `.screenshots/galaxy/m1*`）：
  - 无障碍开：表盘按 Home → 蜂窝；蜂窝按 Home → 表盘；从蜂窝打开应用后按 Home → 表盘；表盘按返回 → 仍是表盘。
  - 无障碍关：表盘第一次按 Home 停在表盘，第二次进蜂窝，之后蜂窝和表盘交替；从蜂窝打开应用后按 Home → 表盘。
  - 回蜂窝约 285ms（启动器每次重建）。
  - 第三轮（`cde3ffd`）：codex 加了只在 debug 包输出的 `N2Home` 诊断日志，系统主屏包名改为运行时刷新，转交后预设“表盘”状态以便自愈。
  - 真机定位“撤销权限后 Home 失效”（`46494c6`，编排者）：三星国行每次查询应用列表时，会把自己的“要允许读取应用程序列表吗”授权框塞进**启动器自己的任务**；我们在 `onStop` 里关任务，把授权框一起关掉了，任务空了系统就再发一次 Home，落回表盘。改为被同任务里的其他界面盖住时不关任务。真机验证：授权框能停住；点“允许”回到蜂窝；点“不允许”后蜂窝照常显示全部 33 个应用；两种状态下 Home 都在表盘和蜂窝之间切换。
  - 三星手表把全局日志级别设成了静默（`persist.log.tag=Settings`），读诊断日志前要先 `adb shell setprop log.tag.N2Home VERBOSE`（重启后失效）。
- M4：DeepSeek V4.1 Flash max，worktree `orch-20261018-011941-258c-mobile`。第一轮（`e25c670`、`0f0ef1b`、`8de5475`）把主题、玻璃组件、全部页面和手表预览换成摩卡玻璃，新增“手表画质”“图标风格”两个同步设置和“Home 键”帮助。看截图发现的问题交给第二轮：
  - 浅色模式下玻璃卡片里透出直角阴影（半透明玻璃上用了系统投影）；
  - 顶栏贴边；
  - 浅色上的香槟色文字和图标太淡，改用 `accentText`；
  - 预览底部圆弧名称压在图标上，加深色光晕（手表端 M3 同步改）；
  - 网格预览的齿轮和第一行重叠；
  - “演示模式”卡片内边距太小。
- M3：codex 做完了全部界面（`9c540e3`、`18737c6`、`ba9c168`），写结果卡前额度用完（17:05 才恢复），编排者直接审查并合并（`e6765f0`）。审查发现的问题交给 droid gpt-6.1-sol 收尾（run `20261018-125736-102d`）：

## 待办与已知问题

- [x] “没有可启动的应用”：两位 agent 共试了十几种情况都没复现，加了一次空目录延迟重试兜底（M1）。
- [x] 三星“读取应用列表”权限：授权框由三星系统自动弹出，允许 / 不允许都能正常使用（M1）。
- [ ] 授权框上按返回只是关掉，下次刷新应用列表时三星会马上再弹；授权框显示期间 Home 键被三星挂起，关掉后才生效。都是三星的行为，暂不处理。
- [x] 清单加了国行版声明 `local_edition_compatible`（M1）。
- [ ] Tile 页按 Home 会打开蜂窝（三星原生是回表盘）；无障碍事件里分不出 Tile 和表盘，暂时保持。
- [ ] 三星 sysui 会记住上次停留的页面：如果用户之前停在三星自带的应用列表，转交 Home 时会显示它，而不是表盘。设 N2 为主屏后基本不会出现。
- [ ] Android Studio 提示 `onRequestPermissionsResult` 已废弃，M3 时改用 Activity Result API。
- [ ] 国行手表的 Data Layer 经过 `com.google.android.wearable.app.cn`，手机和手表的同步从没在真机上跑过；需要一部能开 adb 的配对手机才能实测（M5，等用户确认手机）。
