## 进行中

- M1：codex（gpt-6.1-sol xhigh）两轮完成，已合并进集成分支（`c1dc1ee`）。在用户的 Galaxy Watch5 Pro 上实测（截图 `.screenshots/galaxy/m1*`）：
  - 无障碍开：表盘按 Home → 蜂窝；蜂窝按 Home → 表盘；从蜂窝打开应用后按 Home → 表盘；表盘按返回 → 仍是表盘。
  - 无障碍关：表盘第一次按 Home 停在表盘，第二次进蜂窝，之后蜂窝和表盘交替；从蜂窝打开应用后按 Home → 表盘。
  - 回蜂窝约 285ms（启动器每次重建）。
  - 第三轮（`cde3ffd`）：codex 加了只在 debug 包输出的 `N2Home` 诊断日志，系统主屏包名改为运行时刷新，转交后预设“表盘”状态以便自愈。
  - 真机定位“撤销权限后 Home 失效”（`46494c6`，编排者）：三星国行每次查询应用列表时，会把自己的“要允许读取应用程序列表吗”授权框塞进**启动器自己的任务**；我们在 `onStop` 里关任务，把授权框一起关掉了，任务空了系统就再发一次 Home，落回表盘。改为被同任务里的其他界面盖住时不关任务。真机验证：授权框能停住；点“允许”回到蜂窝；点“不允许”后蜂窝照常显示全部 33 个应用；两种状态下 Home 都在表盘和蜂窝之间切换。
  - 三星手表把全局日志级别设成了静默（`persist.log.tag=Settings`），读诊断日志前要先 `adb shell setprop log.tag.N2Home VERBOSE`（重启后失效）。

- M5 真机验证（2026-10-18 17:10，release 包 `3664451`，截图 `.screenshots/galaxy/m5/`）：
  - Home 键：表盘 → 蜂窝 → 表盘交替；从蜂窝打开的应用按 Home 回表盘；表盘上按返回仍是表盘。
  - 蜂窝里连续上下左右快速滑动约 10 秒，`dumpsys gfxinfo`（手表 60Hz，每帧预算 16.7ms）：

    | 档位 | 卡顿帧 | 中位帧时间 | 90 分位 | 99 分位 |
    | --- | --- | --- | --- | --- |
    | 精致 | 5.5–6.7% | 15–20ms | 23–27ms | 40–53ms |
    | 轻量 | 1.1–1.4% | 11–12ms | 13–15ms | 19–28ms |

    慢的主要在渲染线程（“Frame deadline missed”多，“Slow UI thread”少），精致档的全屏光晕、暗角和齿轮投影是嫌疑；轻量档已经很顺。hyperwear 只有一页 7 个图标、基本不滚动，没有可比数据。

- 亮屏直接显示蜂窝（用户 2026-10-18 晚发现，已修 `c6acc2f`）：
  - **原因：**停在蜂窝时熄屏，启动器按设计关掉自己的任务；任务空了系统自动补发一次 Home，我们把它当成按键又打开了蜂窝；熄屏中蜂窝立刻又被停掉，于是每 1.2 秒循环一次，直到亮屏（也白耗电）。
  - **修复：**只认带 `FROM_HOME_KEY` 的真按键，系统补发的一律交给表盘。
  - **真机验证：**无障碍开、关两种情况下，熄屏再亮屏都是表盘，Home 键切换正常。
  - **另：**排查时发现手表上的无障碍服务被关掉了，已恢复。原因后来查到，见下面“图标加载慢”一节。

- 打开蜂窝时图标半天才出来（用户 2026-10-20 晚反馈，已修 `b38f19e`）：
  - **原因：**
    - 每次按 Home 都会新建 Activity 和 ViewModel，界面从空状态开始。
    - 刷新时，33 个应用的图标全部重新渲染并编码成 PNG，只为算出图标 id，算完才显示第一个图标。
    - 启动时还会同时跑两次这样的刷新：一次来自 onStart，一次来自读到配置。被取消的那次也不会真的停下。
  - **修复：**
    - 图标 id 按“应用 + APK 路径 + 形状”记住。应用更新后 APK 路径会变，所以只有更新才会重新渲染。
    - 新 ViewModel 直接沿用上一次蜂窝显示的内容，第一帧就有图标，后台刷新只替换有变化的部分。
    - 进程刚启动时，先从磁盘读目录快照和图标文件显示出来，再做完整刷新，不和它抢两个 CPU 核。
    - 配置没变时不再刷第二次，被取代的刷新会真正停下。
  - **真机结果**（release 包，33 个应用）：

    | 情况 | 修复前 | 修复后 |
    | --- | --- | --- |
    | 平时按 Home（进程还在） | 2.4–4.3 秒后才出图标 | 第一帧就有，后台刷新约 0.4 秒 |
    | 重启或更新后第一次打开 | 同上或更久 | 约 1.0 秒（代码已编译时；刚装完还没编译时约 4.7 秒） |

  - 进程刚启动的情况很少：系统一直绑定着我们的无障碍服务，进程优先级是 100（可见），基本不会被杀，只有重启、更新、崩溃或强行停止后才会出现。
  - **无障碍服务被关的原因：**安卓在“强行停止”一个应用时，会把它的无障碍服务从已开启列表里删掉。之前测性能时用过 `am force-stop`，所以服务被关了。用户在设置里点“强行停止”也会这样。测试时改用重装来重启进程。
