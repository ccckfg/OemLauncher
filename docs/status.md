- 亮屏直接显示蜂窝（用户 2026-10-18 晚发现，已修 `c6acc2f`）：
  - **原因：**停在蜂窝时熄屏，启动器按设计关掉自己的任务；任务空了系统自动补发一次 Home，我们把它当成按键又打开了蜂窝；熄屏中蜂窝立刻又被停掉，于是每 1.2 秒循环一次，直到亮屏（也白耗电）。
  - **修复：**只认带 `FROM_HOME_KEY` 的真按键，系统补发的一律交给表盘。
  - **真机验证：**无障碍开、关两种情况下，熄屏再亮屏都是表盘，Home 键切换正常。
  - **另：**排查时发现手表上的无障碍服务被关掉了，已恢复。原因后来查到，见下面“图标加载慢”一节。

- 打开蜂窝时图标半天才出来（用户 2026-10-20 晚反馈，已修 `b38f19e`）：
  - **原因：**
    - 每次按 Home 都会新建 Activity 和 ViewModel，界面从空状态开始。
    - 刷新时，33 个应用的图标全部重新渲染并编码成 PNG，只为算出图标 id，算完才显示第一个图标。
    - 启动时还会同时跑两次这样的刷新：一次来自 onStart，一次来自读到配置。被取消的那次也不会真的停下。
  - **修复：**
    - 图标 id 按“应用 + APK 路径 + 形状”记住。应用更新后 APK 路径会变，所以只有更新才会重新渲染。
    - 新 ViewModel 直接沿用上一次蜂窝显示的内容，第一帧就有图标，后台刷新只替换有变化的部分。
    - 进程刚启动时，先从磁盘读目录快照和图标文件显示出来，再做完整刷新，不和它抢两个 CPU 核。
    - 配置没变时不再刷第二次，被取代的刷新会真正停下。
  - **真机结果**（release 包，33 个应用）：

    | 情况 | 修复前 | 修复后 |
    | --- | --- | --- |
    | 平时按 Home（进程还在） | 2.4–4.3 秒后才出图标 | 第一帧就有，后台刷新约 0.4 秒 |
    | 重启或更新后第一次打开 | 同上或更久 | 约 1.0 秒（代码已编译时；刚装完还没编译时约 4.7 秒） |

  - 进程刚启动的情况很少：系统一直绑定着我们的无障碍服务，进程优先级是 100（可见），基本不会被杀，只有重启、更新、崩溃或强行停止后才会出现。
  - **之后（同晚）：**用户反馈桌面出现时没有动画，首次加载也没有，已加（`daa61e7`）：
    - 窗口在表盘上淡入，精致档蜂窝从中心一圈圈展开，规则写进 `docs/design/README.md` 第 8 节。
    - **原因：**Home 中转页启动桌面时特意关了动画。
    - **踩过的坑：**
      - 动画按 Compose 首帧计时的话，系统要等过渡准备好才显示窗口，大半段动画在窗口出现前就播完了。改为等窗口拿到焦点再开始（进入动画完成和 600ms 超时作为后备）。
      - 底部名称用全屏图层做淡入，每帧都要离屏绘制，改为 `ModulateAlpha`。
    - **真机结果：**约 400ms 的入场每次能出 24/25–26 帧（掉 1–2 帧），GPU 帧时间受手表调频影响在 9–19ms 之间波动。窗口淡入和我们的绘制会抢同一块 GPU：关掉系统过渡动画后，GPU 帧时间约减半。
  - **无障碍服务被关的原因：**安卓在“强行停止”一个应用时，会把它的无障碍服务从已开启列表里删掉。之前测性能时用过 `am force-stop`，所以服务被关了。用户在设置里点“强行停止”也会这样。测试时改用重装来重启进程。
